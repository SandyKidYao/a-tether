# A-tether v0.1 内部协议

## Claude Code 适配层

C 直接启动官方 Claude Code CLI。登录检查使用 `claude auth status`；模型目录来自 stream-json 初始化响应。A 选择模型 ID 后，C 使用目录中对应的 Claude 路由发起请求。

每轮请求在私有临时目录中运行一次 `claude -p`。系统提示写入权限为 0600 的文件，按角色标记的消息历史、工具调用 ID 和工具结果通过标准输入传入。图片使用独立的图像内容块。历史记录以文本方式重建，长会话消耗的上下文与 Claude 原生会话可能不同。

C 关闭 CLI 内建工具、钩子和会话持久化，并用严格 MCP 配置加载本项目的只读工具目录。目录只提供 Pi 声明的工具名称、说明和参数结构，拒绝执行请求。C 从 CLI 标准输出接收文本增量和原生工具调用，将已声明的调用翻译为 Pi 事件。A 的 Pi 执行工具后发起下一轮。

## 传输

v0.1 两端只使用回环地址，通过 SSH 本地端口转发连接。所有端点校验 A-tether 自身的 Bearer 令牌。Claude 登录状态仅在 C 检查。A 将上下文中的代码、命令输出及工具结果发送给 C，随后由 Claude Code 发送至模型服务。

| 接口 | 职责 |
| --- | --- |
| GET /v1/health | 报告服务状态、CLI 可用性和登录布尔值 |
| GET /v1/models | 返回 C 发现的模型以及 Pi 注册模型所需的能力字段 |
| POST /v1/requests | 接受 A 生成的 UUID、模型 ID、上下文及白名单生成选项，逐行返回 JSON |
| DELETE /v1/requests/{id} | 幂等取消，触发与连接断开相同的清理 |

每行响应都带请求 ID。event 承载增量，done 承载权威的 Pi 最终消息，error 承载稳定错误码。每轮恰有一个终态，提前 EOF 在 A 显示为连接中断。A 只将最终消息中的工具调用交给 Pi，工具结果随下一轮完整上下文提交。C 从本地目录选择模型定义和 CLI 配置，仅接受白名单字段。

服务端为每个活跃请求维护 AbortController。取消、断连、超时和服务退出均触发中止，等待 CLI 进程组与临时目录清理。认证失败、Claude 未登录、额度耗尽和后端故障分别呈现。服务默认仅打印启动状态和监听端口。

## 联调判据

在 A 的临时项目写入随机标记，要求模型先读取标记，再基于读到的值编辑文件并用本地命令验证。核对 A 文件和命令结果、C 工作目录及子进程。分别在流式输出时取消、关闭 SSH 隧道，检查 Pi 的终态及 C 的资源清理。运行方法与验证环境见 [README](../README.md)。

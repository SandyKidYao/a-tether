# A-tether v0.1 内部协议

## Claude Code 适配层

C 直接启动官方 Claude Code CLI。登录检查使用 `claude auth status`。每轮请求不加载 Claude Code 的设置文件，但 `~/.claude/settings.json`（或 `CLAUDE_CONFIG_DIR` 下）`env` 中的 `CLAUDE_CODE_OAUTH_TOKEN` 会传给 CLI，使登录检查与实际请求一致；模型目录来自 stream-json 初始化响应。A 选择模型 ID 后，C 使用目录中对应的 Claude 路由发起请求。

C 为每个 Pi 会话保留一个 `claude -p` 进程，运行在私有临时目录中，stdin 保持打开，不写会话文件（设计见 [常驻会话](dev/live-session.md)）。系统提示写入权限为 0600 的文件。C 先按 Pi 的规则整理历史（跳过出错和被中止的回复，给没有结果的工具调用补结果）；新进程第一次收到的是按角色标记的完整历史文本，保留工具调用 ID，图片使用独立的图像内容块。之后请求的历史如果正好是进程已有历史的延续——补上它在等的工具结果，或在它空闲时追加新的 user 消息——就以原生形式交给同一个进程；否则用完整历史重启一个进程。进程空闲 60 分钟或超过 `server.maxSessions` 时回收。

C 关闭 CLI 内建工具、钩子、会话持久化和自动压缩（上下文由 Pi 压缩），并通过 `sdk` 类型的 MCP server 向 CLI 提供 Pi 声明的工具名称、说明和参数结构。CLI 调用工具时，C 把调用交给 A，挂起这次 MCP 调用，等 Pi 在下一轮请求中带来结果后再返回。Pi 中途修改工具集时，C 通知 CLI 重新拉取工具列表。历史记录中的工具调用和工具结果使用 Claude 实际调用的名称（`mcp__tether__` 前缀）。C 从 CLI 标准输出接收文本增量和原生工具调用，将其翻译为 Pi 事件：带前缀或不带前缀的已声明名称都还原为 Pi 名称，其他名称原样交给 Pi，由 Pi 返回“工具不存在”的结果，参数不是对象时传空对象由 Pi 校验，模型在下一轮自行纠正。A 的 Pi 执行工具后发起下一轮。

## 传输

v0.1 默认两端只使用回环地址，通过端口转发（推荐 SSH 本地端口转发）连接；C 可以用 `server.host` 改为监听局域网地址，此时令牌以明文 HTTP 传输。所有端点校验 A-tether 自身的 Bearer 令牌。Claude 登录状态仅在 C 检查。A 将上下文中的代码、命令输出及工具结果发送给 C，随后由 Claude Code 发送至模型服务。

| 接口 | 职责 |
| --- | --- |
| GET /v1/health | 报告服务状态、CLI 可用性和登录布尔值，以及常驻进程的数量和启动、复用次数 |
| GET /v1/models | 返回 C 发现的模型以及 Pi 注册模型所需的能力字段 |
| POST /v1/turns/{id} | 发起一个回合：A 生成的 UUID、模型 ID、增量形式的上下文及白名单生成选项。响应是这个回合的事件流 |
| GET /v1/turns/{id}/events?after=N | 从第 N 帧之后接着收同一个回合；C 上没有这个回合时返回 404 `gone` |
| DELETE /v1/turns/{id} | 幂等。回合在进行就取消，已结束就释放它的缓冲 |
| POST /v1/ping | A 的心跳，Pi 运行期间一直发，与有没有回合无关 |
| POST /v1/bye | Pi 退出时通知 C |
| POST /v1/probe?reply=N | 链路体检用：接收任意字节，返回 N 个随机字节，不压缩 |

### 回合与连接

一个回合是模型的一次回复。它在 C 上独立于任何连接：C 给回合的每一帧编号（从 1 起，不跳号）并留在内存里，连接只是读它的窗口。连接断开，回合照常进行；A 再连上时报出已经收到第几帧，C 从下一帧补发。所以网络抖动不结束 Claude 进程，生成过的内容也不重新生成。

事件流每行一帧 JSON。`event` 承载增量，`done` 承载权威的 Pi 最终消息，`error` 承载稳定错误码，三者带序号 `n`；`heartbeat` 是心跳，不占序号，带最新序号、回合已运行的时间、模型多久没有输出、C 多久前收到过 A 的消息（毫秒）。每个回合恰有一个终态帧。C 读完请求体就返回响应头，此后模型查找失败等所有结果都以 `error` 帧返回。A 只将最终消息中的工具调用交给 Pi，工具结果随下一个回合提交。

回合只在四种情况下结束：生成完成；A 取消（DELETE、ping 里的 `released`、bye）；C 的控制台取消；A 失联超过 `server.heartbeatTimeout`（原因 `lost`，日志记为 `lost: no heartbeat from A for Ns`）。前三种之外，连接状态不影响回合。

结束后的回合留在 C 上，直到 A 释放它：生成完成的最多留 10 分钟，失败的留 1 分钟，让重连的 A 读到原因。A 收到终态帧后用 DELETE 释放，并在随后的 ping 里重复一次。A 因为连不上而放弃时不释放：回合可能已经在 C 上完成。

**相同上下文不生成第二次。** 发起回合时，C 用模型、生成选项和上下文算出指纹。指纹相同的回合还在进行或已完成未释放时，新的回合 ID 直接接到它上面，从第 1 帧重放。Pi 在连接类错误后的自动重试、用户手动重发，都落在这里。被取消和失败的回合不重放。接上去时，原来的回合如果已经没有连接在读，新的回合 ID 接管它，旧 ID 随之失效；还有连接在读时两个 ID 共用这个回合，都释放之后回合才结束。

同一个回合 ID 再次 POST（上一次的响应丢了）不会开第二个回合，而是接到已有的回合上。一个回合同一时间只有一条连接在读，新连接顶替旧连接。

### 增量上下文

C 在服务进程的内存里保留收到过的历史，A 每个回合只发新增的部分。两端都不需要会话标识：

- 消息的摘要是 `sha256(JSON.stringify(消息))`，base64url 编码。
- 一段历史的链式摘要是 `chain_i = sha256(chain_{i-1} + ":" + 摘要_i)`，`chain_0` 为空串。
- 请求体的 `context` 是 `{base?: {count, chain}, add: [...]}`：`base` 指 C 已经持有的前 `count` 条历史，`add` 是其后的消息。`add` 里 C 自己生成的回复写成 `{"$ref": 摘要}`，不传回内容。
- C 没有 `base` 指的历史，或没有 `$ref` 指的回复时，返回 409 `resync`。A 清空自己对 C 的认识，用同一个回合 ID 改发完整上下文（没有 `base`，没有 `$ref`）。C 重启、内存淘汰、Pi 压缩上下文或切换分支之后都走这条路。

C 把增量拼回完整历史后交给后端，后端看到的仍是完整上下文。这些历史只在内存里，不落盘：最多保留最近用到的 64 份、合计 256 MiB，超出时淘汰最久没用的；服务退出时全部释放。

### 压缩

超过 512 字节的请求体用 brotli 压缩（`content-encoding: br`），解压后仍以 32 MiB 为上限。A 声明 `accept-encoding: br` 时，事件流用 brotli 流式压缩，C 把约 40 毫秒内的帧合并成一次写入并刷新。最终消息里与增量重复的内容由压缩折叠，事件的含义不变。`/v1/probe` 两个方向都不压缩。

### 版本、心跳与在线状态

两端在每个请求和响应上都带 `a-tether-protocol` 头（当前为 `4`）和 `a-tether-version` 头（包版本）。协议值不一致时 C 返回错误码 `version`，A 显示两端各自的版本；两端须同时升级。A 收到没有协议头的响应时，认定它不是 A-tether 服务发出的（端口转发、代理，或 Node 自己对坏请求的回答），报连接类错误并写明 HTTP 状态码，不报版本不一致。

A 在每个请求上另带两个头，供 C 的监控界面区分不同的 A：`a-tether-client` 是 12 位十六进制随机 ID，每个 Pi 进程生成一次，只在内存里；`a-tether-host` 是 A 的主机名（去掉 `.local`，只保留可打印 ASCII，最多 64 字符）。C 只在令牌校验和版本检查通过后记录它们；缺少或格式不对时不拒绝请求，按来源地址归为「未标识」。

C 在事件流和 ping 的响应头里给出 `a-tether-heartbeat-interval` 和 `a-tether-heartbeat-timeout`（毫秒，来自 C 的 `server.heartbeatInterval` 和 `server.heartbeatTimeout`），之后：

- A 每个间隔发一次 ping：`{turns: {回合 ID: 已收到第几帧}, released: [不再需要的回合], rtt}`。C 回 `{loggedIn, turns: {回合 ID: {n, state}}}`。ping 复用一条保持打开的连接，A 用它的往返时间作为延迟。
- C 据此判断 A 的状态：有回合在进行是「请求中」；ping 正常是「空闲」；超过 3 个间隔没有 ping 是「失联」；收到 bye 是「已退出」。
- 回合进行中，C 每个间隔向事件流写一行 `heartbeat`。A 的连接超过 2.5 个间隔没有收到任何字节时，换一条连接续传。
- A 累计超过时限没有收到这个回合的任何数据时放弃，错误信息引用最后一次心跳的内容。发起回合时上传没有进度可看，所以再按请求体大小多给一些时间（按 4 KB/s 计）。
- C 超过时限没有收到 A 关于某个回合的消息（ping 里列出它，或连接接上它）时，以原因 `lost` 中止这个回合，结束 Claude 进程。
- 上传请求体没有总时长上限；连续超过时限没有收到数据时，C 以 `stalled` 结束这次上传。

bye 让 C 立即取消这个 A 的回合，把它标为已退出，并让它的空闲 Claude 进程在 `server.exitGrace` 秒后回收（期间再有请求用到就恢复原来的空闲期限）；进程池满时先淘汰这些进程。A 只在 Pi 进程退出时发 bye，等待不超过 1.5 秒。

连接类错误（无法连接、重连无果、`lost`、`gone`、非 A-tether 的响应）的提示包含 Pi 自动重试能识别的英文短语，由 Pi 按退避重发；格式错误、版本不一致等不会重试。发起回合时连接被拒绝（没有服务在监听）或收到非 A-tether 的响应，插件不在内部重试，直接报错；回合已经在 C 上开始之后遇到这两种情况，按连接中断处理，继续重连。

服务端为每个回合维护 AbortController。取消和 A 失联会结束这个回合的 Claude 进程；服务退出时结束所有进程，并等待进程组与临时目录清理。认证失败、Claude 未登录、额度耗尽和后端故障分别呈现。服务在终端里运行时显示监控界面，否则仅打印启动状态、监听端口和失败诊断；监控数据只在 C 的内存里，不经 HTTP 暴露。

## 联调判据

在 A 的临时项目写入随机标记，要求模型先读取标记，再基于读到的值编辑文件并用本地命令验证。核对 A 文件和命令结果、C 工作目录及子进程。分别在流式输出时取消、短暂关闭 SSH 隧道后恢复、长时间关闭 SSH 隧道，检查 Pi 的终态、回复是否完整及 C 的资源清理。运行方法与验证环境见 [开发说明](dev/development.md)。
